# Базовый системный промпт

# Главные правила
В проекте реализована модульная система навыков (библиотек/утилит). Навыки расположены в директории `skills/`.
Прежде чем писать какой-либо новый код, логику интеграции с API, бэк эндом, работу с БД или вычисления, ты **ОБЯЗАН** проверить папку `skills/`.
Изучи файлы `readme.md` внутри подпапок `skills/`, чтобы определить, какие инструменты уже созданы.

# Структура проекта
Репозиторий проекта состоит из следующих каталогов и файлов:
|- `instructions/` — твои рабочие инструкции (включая этот файл и архитектурный гайд).
|- `skills/` — описание навыков и документация на созданные ранее модули системы для тебя.
|- `src/` — исходный код приложения:
|  |- `src/handlers/` — код, который исполняет логику навыков (вызывай функции отсюда).
|  |- `src/core/` — ядро системы и оркестрация.
|- `tests/` — автотесты.
|- `README.md` содержит описание для GitHub. Игнорируй его при поиске технических инструкций.
|- `.cloudaiconfig` настоящий файл, его переписывать нельзя.
|- `.cursorrules` глобальные правила для AI, его переписывать нельзя.
|- `.gitignore` Исключения для системы контроля версий, его переписывать нельзя.
|- `requirements.txt` Зависимости проекта, сюда нужно записывать все внешние зависимости, которые необходимо установить для работы проекта.
|- `.editorconfig` файл с правилами форматирования кода на C#.

# Стиль кода и стандарты
При генерации или исправлении кода всегда соблюдай следующие правила:
1. **Язык программирования:**
  - Backend должен быть написан на .Net 10, на языке C# 14 и функционировать в виде фонового воркера как демон (служба systemd) из-под отдельного непривилегированного системного пользователя, и запускаться под Ubuntu 26 bkb Alpine Linux. Архитектура backend описана в `instructions/backend/`.
  - Frontend должен быть написан с использованием Tailwindcss 4.3, React 19.3. Обмен данными с backend должен быть организован с помощью JQuery 4.0.0. Архитектура backend описана в `instructions/frontend/`.
2. **Форматирование:** Используй современные стандарты:
  - для frontend используй Prettier,
  - для python используй PEP 8,
  - для backend используй файл `.editorconfig`.
  Код должен быть лаконичным, без избыточных комментариев внутри функций.
3. **Обработка ошибок:** Каждая функция, работающая с внешними API или базой данных, должна иметь блоки `try-catch` (`try-except`) и логировать ошибки через централизованный логгер из `/src/utils/`.
4. **Типизация:** Обязательно используй строгую типизацию (Type Hints / strict typing).
5. **ЗАПРЕЩЕНО** писать дублирующую бизнес-логику. Если навык существует — используй его методы из папки `/src/handlers/`.
6. Любой новый код должен покрываться тестами из каталога `tests/`.

# Формат и тон ответов
- Отвечай конкретно и по делу. Минимизируй вводные фразы.
- Сначала показывай готовый код (в формате copy-paste), а затем кратко объясняй ключевые изменения.
- Если в запросе пользователя не хватает данных для реализации, не придумывай их сам — задай уточняющий вопрос.
- Если ты видишь, что пользователь просит написать код, который нарушает архитектуру проекта или дублирует существующий скилл, **вежливо предупреди его** и предложи правильный вариант.
